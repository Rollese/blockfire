# M20 Stats & Analytics — P1 Live Gate Evidence (2026-07-11)

**Verdict: PASS.** The full P1 pipeline works end-to-end: the game-server `StatsReporter`
(P1-B) accumulates per-player / per-weapon counters + per-kill events during a real bot
match and delivers them to the P1-A ingest API, which persists them to Postgres — with a
local NDJSON spool that loses **no data** across a backend outage.

Run locally on game2 (Godot 4.7 dedicated server + separate bot-driver process, both against
the `backend/` docker-compose stack). Gate script: `docker/run-stats-p1-gate.sh`.

## Setup

```bash
cd backend && export INGEST_TOKEN=dev-secret && docker compose up --build -d
curl -s localhost:8000/healthz            # {"status":"ok"}
```

Server + bots per match (unique port, canonical gameplay map):

```bash
godot --headless --path . -- --server --port=28123 --map=conquest_town --tickets=30 \
  --time-limit=240 --stats-endpoint=http://localhost:8000 --stats-token=dev-secret &
godot --headless --path . -- --bots --bot-count=24 --port=28123 --map=conquest_town &
# ...play to `[match] OVER`, then stop both.
```

## Step 4 — backend-down loses no data (the P1 durability guarantee)

1. Match A finished with the backend up → spool file drained to **0 lines** (all delivered).
2. `docker compose stop api` (db kept up). Match B played to `OVER` **entirely while the API
   was down**. The spool captured everything — **6 records: 5 `/ingest/events` batches + 1
   `/ingest/match` report** (`~/.local/share/godot/app_userdata/Blockfire/stats_spool.ndjson`).
   (The match report being spooled — not lost — exercises the `end_match` self-drain fix.)
3. `docker compose start api`. Match C played with the API back up. Its first successful POST
   drained match B's backlog: spool returned to **0 lines**, and Postgres now holds **3 complete
   matches** — including the outage match `1783801225-6603` (58s, 24 players, 9 kill events),
   recovered in full. No data lost.
