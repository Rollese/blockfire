### Assertions

1. **Leaderboard JSON** `GET /api/leaderboard?sort=kills&limit=5` returns players with non-zero kills;
   top = `name:bot-23` (2 kills). Variant weapon keys present (`m4a2`, `m245 saw`) — the weapon-variants
   registry flows through to profiles.
2. **Rollup faithfulness** — `GET /api/players/name:bot-23` `total_kills` **== direct SQL aggregate**
   `SELECT sum(kills) FROM match_players WHERE player_key='name:bot-23'` → both **2**. The worker rollup
   is a faithful reduction of the raw match tables.
3. **Web pages** — `GET /` → **200**, `GET /players/name:bot-23` → **200**; the profile page renders the
   player's top weapon `m4a2`.
4. **Dormant paths present-but-inert** — worker logged **0** `enriched` lines (Steam enrichment is a clean
   no-op with no `STEAM_WEB_API_KEY`); `GET /login` → **302** to

  activate automatically once real Steam clients connect and a `STEAM_WEB_API_KEY` is configured — no
  producer or rollup change needed (`register_player`/enrichment already read `steam_id`).
- `total_playtime_s`, assists/captures/xp remain 0 where the P1 producer defers them (unchanged from P1-B).
- Profile-link hrefs are not URL-encoded; harmless for the sanitized name/numeric-Steam identity keys in
  use. Worth `|urlencode` if identity keys ever admit URL-significant characters.
