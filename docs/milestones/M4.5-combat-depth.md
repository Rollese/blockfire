## Scope

### Movement extensions

- **Ladder climbing:** detect ladder-tagged geometry (special `LADDER` material on structure faces or map geometry); special movement mode — constant y-velocity upward while `CLIMB` button held, no gravity, limited horizontal strafe. Server-authoritative; client predicts. Snap to top/bottom anchor on exit.
- **Vaulting:** detect low obstacle (waist-height AABB) ahead while standing/moving; short vault — continuous server-side position delta over `VAULT_TICKS`, auto-triggered (no button in v1). No vaulting while crouched/prone.
- **Drop-shoot prevention:** server tracks `last_stance_change_tick` per pawn. Fire is blocked for `PRONE_TRANSITION_TICKS` after a stand/crouch → prone transition. Eliminates the drop-shoot exploit (gain prone hitbox advantage and fire in the same transition window). Standing → crouch is not penalised (smaller advantage, smaller penalty; revisit in balance pass).
- **Explicit non-scope:** no sliding (design decision — not in Blockfire v1), no parachutes (design decision), no swimming / water movement (design decision).

### DBNO / bleed-out / revive / bandages

All players start with `BANDAGE_COUNT` bandages per spawn. Health reaching 0 moves a pawn to DOWNED (bleed-out) state rather than instant death.

- **DOWNED state:** `health ≤ 0 → state = DOWNED`, not `alive = false`. Downed pawn is immobile (crawl only, `DOWNED_CRAWL_SPEED`), cannot fire, bleeds at `BLEED_RATE` health per tick. Server still simulates and replicates the pawn (other players see the downed body).
- **Bleed-out:** after `health` reaches `BLEEDOUT_FLOOR` (hard minimum, cannot self-stop below this), pawn transitions to `alive = false` → normal respawn path.
- **Self-bandage:** use a bandage on self to **halt bleed** (stops further health drain; does not restore HP). Cannot self-revive from DOWNED.
- **Revive:** stand within `REVIVE_RANGE` of a DOWNED teammate; hold action for `REVIVE_TICKS`. On completion: teammate stands at `REVIVE_HP` health (no longer DOWNED). Server validates proximity + DOWNED state + bandage count.
- **Medic:** `REVIVE_TICKS / 2` (2× revive speed) — the only class differentiation on the bandage mechanic.
- Bandage count does not regenerate mid-life; replenished on spawn and via Support ammo bags (M4.5 scope).

### Body dragging — DESCOPED (never shipped)

> **Not implemented.** `GRAB_BODY`/`RELEASE_BODY`/`carrier_id` have **zero code hits** in `shared/`+`server/` — the mechanic was descoped during M4.5 and never built (it needs its own sim+wire increment). Confirmed again at M7.5 (see `M7.5-bot-intelligence.md`, "drag-to-safety descoped"). The original design is retained below for whenever it's picked up.

- Any alive player can grab a DOWNED or dead corpse within `GRAB_RANGE`.
- **Server state:** `carrier_id` on the DOWNED/corpse record; validated (carrier alive, within range, not sprinting). Released on carrier death or explicit drop input.
- **Replicated:** `{carrier_id, corpse_id}` — two integers on the snapshot. Other clients derive position from the carrier's snapshot position + a fixed grab offset.
- **Client:** anchor the ragdoll root to the carrier's interpolated position + offset; limbs hang kinematically.

### Class gadget system

All gadget inputs sent over the INPUT channel; all validation and state authoritative on the server. Gadgets are data-driven in `data/gadgets.json`. Each class gets a gadget slot (or two) in addition to the primary weapon.

| Class | Gadget A | Gadget B |
|---|---|---|
| Assault | Frag grenade (M4) | Smoke grenade (M4) |
| Medic | Bandage kit (2× revive speed, +`MEDIC_EXTRA_BANDAGES` charges) | Medic bag (deployable; see below) |
| Engineer | C4 (remote detonation; see below) | Vehicle repair kit *(M5 — defined here, implemented in M5)* |
| Support | Ammo bag (deployable resupply; see below) | *(open slot v1)* |
| Recon | Claymore / mine (proximity trigger; see below) | *(open slot v1)* |

**RPG / rocket launcher:** projectile anti-vehicle/anti-structure weapon available as a **weapon-slot choice** (not a gadget slot) for all classes. Server-side arc trajectory (reuses the `Grenade` ballistic model from M4). Detonates on structure/vehicle/ground contact. Area damage: structures (`BLAST_CELL_RADIUS`) + pawns (sphere, linear falloff, FF-off, present-time — same model as frag grenades). `ROCKET_COOLDOWN_TICKS` between shots; carry `MAX_ROCKETS` per spawn. Anti-vehicle damage applies to vehicle HP (M5 path; RPG already deals structure + pawn damage with this milestone, vehicle damage wired in M5).

**C4 (Engineer):** place on any surface (structure cell face or flat ground). Sticks at placement point. Up to `MAX_C4_PLACED` active at once. Second gadget-use: remote detonation of all owned C4 simultaneously. Server tracks placed C4 as entities `{owner, pos, cell_or_surface, tick_placed}`; detonation = blast at position (same `ids_in_radius` + pawn sphere path as grenades, FF-off). C4 attached to a structure cell is removed when that cell is destroyed.

**Ammo bag (Support):** deploy on ground at player feet. Server tracks `{owner, pos, tick_placed, resupply_remaining}`. Any teammate within `RESUPPLY_RADIUS` who presses the action button receives a full ammo + bandage refill. `resupply_remaining` decrements per use; bag disappears when exhausted. Max `MAX_BAGS_PER_PLAYER` deployed simultaneously.

**Claymore / mine (Recon):** place on flat surface within `MINE_PLACE_RANGE`. Server tracks `{owner, pos, facing, tick_placed, armed_after_tick}`. Each tick, check if any enemy pawn enters `MINE_TRIGGER_RADIUS` and the mine is armed; on trigger: directional blast cone (claymore) or omnidirectional sphere (mine), falloff damage, FF-off. Max `MAX_MINES_PER_PLAYER` placed.

**Medic bag (Medic):** deployable bag. Server tracks `{owner, pos, hp_pool_remaining}`. Teammates within `MEDIC_BAG_RADIUS` passively regenerate HP at `MEDIC_REGEN_RATE` per tick up to `MEDIC_BAG_MAX_GIVE` total HP. Does not revive.

### Weapon attachments

Three attachment slots per weapon: **Optic**, **Barrel**, **Underbarrel**. Data-driven in `data/attachments.json`. Attachments apply stat multipliers to the base weapon record at combat-resolution time. Selection is part of the loadout (set pre-match / at deploy screen); no mid-match attachment swapping.

| Slot | Options (v1) | Stat effect |
|---|---|---|
| Optic | Iron sights (default), Red dot, 2× scope, 4× scope | `spread_base_deg` multiplier; scope zoom is client-side (M7) |
| Barrel | Standard (default), Suppressor, Muzzle brake | Suppressor: negligible range drop, audio signature (client M7); Brake: recoil pitch multiplier |
| Underbarrel | None (default), Vertical grip, Bipod | Grip: `spread_move_penalty_deg` multiplier; Bipod (prone only): eliminates spread entirely |

`loadout.gd` gains `attachments: Dictionary` (slot → attachment ID). Server applies multipliers in `combat.gd` before hit resolution. No attachment affects lag-comp or server authority.

### Bullet penetration

Material tag `material` added to each piece type in `fortifications.json`: `WOOD`, `METAL_THIN`, `CONCRETE`, `METAL_THICK`.

`combat.gd` `march()` extended: on hitting a penetrable piece, apply `weapon.damage_body × absorption` to the piece; if piece survives (health > 0), continue the ray with `remaining_damage × transmit_factor` toward the next target. Max **1 penetration per shot** in v1.

| Material | Penetrable | Absorption (damage to piece) | Transmit factor (damage continues) |
|---|---|---|---|
| WOOD | Yes | 0.40 | 0.60 |
| METAL_THIN | Yes | 0.65 | 0.35 |
| CONCRETE | No | — | — |
| METAL_THICK | No | — | — |

Piece removal and bucket-delta follow the M4 Phase 2 path. Penetration does not change the lag-comp rewind: the shot still resolves against rewound enemy positions; the material absorption is applied after the ray exits the structure, using current (non-rewound) remaining damage.

## Budgets

- **Server tick:** mean step **< 33.3 ms** at 128 bots (30 Hz held), stacking onto M4's 30.89 ms peak. New per-tick work: DBNO/bleed O(N downed), gadget entity tick O(deployed entities), penetration O(1) extra march step, drop-shoot gate O(1) per fire, mine proximity O(mines × pawns in range). Profile early — headroom is thin.
- **Bandwidth:** DOWNED state + carrier_id added to snapshot (≤2 bytes per pawn); gadget deploy/detonate events are reliable CONTROL (low frequency, not per-tick). No per-tick gadget-entity stream.
