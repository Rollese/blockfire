**Objective:** Replace today's reflex bots (`fight nearest enemy`, `bots/bot_driver.gd`)
with tactical, **human-like, fair-play** infantry AI good enough to **backfill real
128-player matches** alongside and against humans. Bots reason only from their
interest-managed view, behave believably (reaction delay, imperfect aim), and stay
**anti-cheat-clean** (ordinary validated inputs; human-shaped behaviour distributions that
do not trip Layer-4 statistical detection — see [ADR-0004](../adr/0004-anti-cheat-and-skill-matchmaking.md)).
A server-authorized **admin free-fly spectator** lets a designated operator fly the map and
evaluate bot behaviour visually, then tune from what they see.

## Standing constraints (ratified during brainstorm)

1. **Fair-play perception.** Bots use **only the interest snapshot** a real client receives
   (already true today). No omniscience; no reading server-internal state.
2. **Human-like conduct.** Reaction delay, aim error + settle, and attention limits are
   first-class and tunable. Bots must look human under the free-cam and read as human to
   Layer-4 detection.
3. **AI is client-side.** All decision-making runs in the **bot-driver processes, off the
   30 Hz server tick**. AI stays **out of `shared/`**. The new budget is bot-driver CPU
   across the Docker fleet, not the server step.

## Architecture — utility scoring + per-squad blackboard

Five layers, all in the bot-driver:

- **Perception** — builds a per-bot **world model** from the interest snapshot (visible
  enemies / allies / downed allies / deployables / cover / objective states), plus
  **short-term memory** (last-known enemy positions, decaying over time), plus a
  **reaction-delay gate**: a freshly-perceived enemy is not actionable until the bot's
  reaction time elapses.
- **Squad blackboard** — knowledge shared among squadmates (fair: models squad voice
  comms): spotted enemies, the focus-fire target, role assignment, and support requests
  (`need_medic`, `need_ammo`).
- **Commander** — a cheap per-squad function assigning **ATTACK vs DEFEND** roles from
  match / flag-ownership state. Builds on M3 squads. Rebalances when an owned flag is
  threatened.
- **Decision** — scores candidate behaviours via **tunable utility curves** over the world
  model, with **hysteresis** to prevent per-tick flip-flopping. Highest-utility behaviour
  wins.
- **Execution + Humanization** — small per-behaviour **FSMs** emit low-level primitives
  (move-to / aim-at / fire-burst / crouch / prone / throw gadget / use gadget / revive /
  drag / climb / vault), wrapped by an aim-error + settle-time + attention model and the
  active **difficulty profile**.

```
score(take_cover)   = f(incoming_fire, health, cover_nearby)
score(revive)       = f(downed_ally_near, threat_low, role)
score(suppress)     = f(enemy_last_known, ammo, squad_focus)
score(push_obj)     = f(obj_contested, squad_role == ATTACK)
score(defend_obj)   = f(obj_owned_threatened, squad_role == DEFEND)
  -> argmax (with hysteresis) -> run behaviour FSM -> humanized primitives
```

## Behaviour catalog

**Core combat (P2)**
- **Stop-to-shoot** — halt or minimise movement while firing (accuracy + human read).
- **Seek cover under fire** — on incoming fire / low health, move to nearest cover and
  **crouch or prone** behind it; **peek → fire → retract**. Uses M4 structures + terrain.
- **Stance control** — crouch/prone for accuracy and smaller profile; respects the M4.5
  drop-shoot fire-gate.
- **Target prioritization** — not "nearest": prefer low-HP, reviving medics, flag-cappers,
  and whoever is actively shooting this bot.
- **Suppressive fire** — keep firing at an enemy's **last-known position** to pin a ducked
  target.
- **Grenades** — **frag** at entrenched / clustered enemies behind cover; **smoke** to
  cross open ground or to screen a revive / advance.
- **Threat-aware retreat / regroup** — low HP → break contact, fall back to cover / medic /
  ammo, regroup with squad.

**Support & survivability (P3)**
- **Revive** downed allies, **medic-priority**; **self-bandage** to halt bleed when downed;
  **medic bag** deploy for passive regen.
- **Drag-to-safety** — pull a downed ally behind cover before reviving (M4.5 body drag).
  *(Descoped 2026-07-03 — the body-drag sim mechanic doesn't exist; needs its own sim+wire
  increment first. See the P3 completion note above.)*
- **Resupply** — Support deploys **ammo bags**; low bots path to friendly bags; requests
  routed via the blackboard *(blackboard routing → P4; P3 shipped self-directed bag-seek)*.
- **Grenade & mine avoidance** — flee visible thrown grenades and detected mines/claymores.
- **Per-class gadget usage** — the full M4.5 kit used appropriately (Assault frag/smoke,
  Medic bag + revive, Support ammo bag, Engineer C4, Recon mines/claymore, RPG vs heavy
  cover).
- **Navigation** — use **ladders / vaults** (M4.5 movement) when pathing requires.

**Squad & strategy (P4)**
- **Commander roles** — defenders hold captured flags; attackers push contested / enemy
  points; **dynamic rebalancing** when an owned flag is threatened.
- **Focus fire** — squadmates concentrate on the blackboard target.
- **Spacing / anti-bunching + basic flanking** — avoid clustering (grenade bait); don't all
  take one lane.
- **Defensive emplacements** — Recon claymores and Engineer C4/mines covering owned-flag
  approaches.

## Humanization & difficulty

Reaction delay, aim-error cone + settle time, and attention / perception limits, packaged
into named **difficulty profiles** (e.g. Recruit / Regular / Veteran / Elite) as data
bundles in `ai_tuning.json`. This is also the anti-cheat story: human-shaped hit-rate and
behaviour distributions mean Layer-4 won't flag bots, and they send ordinary validated
inputs. **Difficulty → ADR-0004 skill-tier mapping is deferred to M9**; M7.5 only exposes
the knobs.

## Spectator & observability (admin free-fly) — built first (P1)

- **Server**: an **admin SteamID allowlist** (the operator's account always included) in
  server config; a **spectator role** the server treats as **non-combat** and **exempts
  from movement validation and excludes from Layer-4 statistics**, so free-flying can't
  self-flag. VAC is not tripped — free-cam is a sanctioned built-in mode, not injection.
- **Client (on M7's renderer)**: an **F-key** (default **F9**, rebindable) toggles free-fly.
  Tools: **bot-AI debug overlay** (per-bot role / state / target / chosen-cover / intent
  gizmos) and **follow / possess a bot** (camera lock + optional decision log). No
  time-controls, no capture (cut as YAGNI).
- **Debug data path**: bots publish a compact **intent packet** (role, state, target_id,
  cover_pos) over an **admin-only debug channel** the server relays **only to admin
  spectators** — dev-only, gated, disabled in production builds.

subagent-driven-development, in the M4.5 mould.

## Constants (initial values; gate-tuned)

| Const | Value | Meaning |
|---|---|---|
| `AI_TICK_EVERY` | 3 | run the decision layer every N server ticks (cost knob) |
| `REACTION_DELAY_TICKS` | 9 (~0.3 s) | ticks before a newly-seen enemy becomes actionable (profile-scaled) |
| `AIM_ERROR_DEG` | 3.0 | base aim cone half-angle before settle (profile-scaled) |
| `AIM_SETTLE_TICKS` | 6 | ticks for aim error to converge onto a tracked target |
| `MEMORY_DECAY_TICKS` | 90 (3 s) | last-known enemy position lifetime |
| `COVER_SEEK_HP_FRAC` | 0.5 | health fraction below which cover-seek utility spikes |
| `RETREAT_HP_FRAC` | 0.25 | health fraction below which retreat dominates |
| `BLACKBOARD_RANGE` | squad | knowledge sharing is squad-scoped (models voice) |
| `SPECTATOR_FLY_KEY` | F9 | client free-fly toggle (rebindable) |

## Budgets

- **Server tick:** essentially unaffected — AI is client-side. The spectator pawn and the
  admin-only debug intent relay are admin-gated, dev-oriented, and negligible.
- **Bot-driver CPU (the new budget):** AI runs at reduced cadence (`AI_TICK_EVERY`) so the
  fleet still sustains 128 bots. Profile early; degrade gracefully (raise cadence / simplify
  scoring) before dropping bot count.
- **Bandwidth:** the debug intent channel is admin-only and off in production; no per-tick
  cost to normal clients.

## Gate

128-bot, 2-team Conquest match with the new AI enabled. Telemetry asserts:

- **Cover under fire:** bots take cover + change stance when fired on (cover-occupancy /
  stance-change events).
- **Stop-to-shoot:** movement-while-firing below a threshold.
- **Revive / support:** revive completions; resupply events; medic-priority observed.
- **Role split:** defenders present on owned flags, attackers on contested points.
- **Tactical gadget use:** frag-vs-cover throws; defensive emplacement kills.
- **Humanized accuracy:** bot hit-rate / reaction distributions fall within a human band
  (i.e. Layer-4 would not flag them).
- **Budgets:** tick + bandwidth held; **bot-driver CPU scales to 128**.
- **Conquest** still reaches a winner.
- **Human sign-off (the real gate):** the operator flies the free-cam, watches the bots, and
  approves the behaviour — the iterate-from-watching loop this milestone exists to enable.
