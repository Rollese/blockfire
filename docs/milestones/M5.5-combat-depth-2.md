## Key design decisions (from the brainstorm, owner-approved 2026-06-17)

- **Stepped projectiles**, not analytic hit-scan-with-drop: bullets are genuine entities, dodgeable, lead-required — the real BattleBit feel. Present-time stepping, **no per-step lag-comp rewind** (travel masks latency). Spawn at the shooter's command tick. Projectiles ride a server pool (disjoint ID range), **not** the per-tick snapshot — clients derive a cosmetic tracer from the fire event.
- **Suppression is gameplay-affecting** (raises effective spread + aim-sway while suppressed), not visual-only; the 1-byte scalar also drives the M7 screen FX.
- **Armor is one simplified class** (Light/Medium/Heavy) bundling body-damage reduction + move-speed + capacity, helmet folded in — not separate helmet/vest/backpack slots.
- **Death feedback is a lightweight recap card** (killer/weapon/distance/HP), **not** a replay killcam (BattleBit has no killcam; no position reveal) — and it lives in **M7-P1**, not here.
- **Audio** is reserved as an M7-P2 spec (designing it before the renderer exists is premature).

## Budgets

- **Server tick** mean step **< 33.3 ms** at 128 bots. **P1 projectiles are the headline risk** (O(live bullets × broadphase steps)); cap (`MAX_LIVE_PROJECTILES`) + ttl + interest-grid culling bound it; degrade the projectile cap before dropping bot count. P2/P3 add cheap O(N)/O(1) work next to the dominant `snap` cost.
- **Bandwidth:** no new per-tick stream; suppression + blind add ≤2 bytes/pawn.

## Gate

Per phase: mechanics proven **deterministically** (scripted scenario — led shot connects with drop; HEAVY takes less than LIGHT; suppressed spread rises; back-stab instant-kills; flash blinds in-LOS; impact detonates on contact), **budget + match completion** proven on the **128-bot fleet** (AI-dependent combat counters reported, not gated — AGENTS.md §10). All phases: Conquest still reaches a winner.

## P1 — Ballistics & weapon handling — CLOSED ✅ (2026-06-23)

Plan: [`docs/plans/2026-06-17-m5.5-p1-ballistics.md`](../plans/2026-06-17-m5.5-p1-ballistics.md) (8 tasks). Built on branch `m5.5-p1-ballistics` via `subagent-driven-development` (Task 3 — the authoritative fire-path change — two-stage read-only reviewed; full-implementation final review = READY TO MERGE). 11 commits; suite **672 run / 0 failed**.

**What shipped:**
- **Stepped projectiles** replace hit-scan. `_fire_shot` spawns a projectile into a server pool (`MAX_LIVE_PROJECTILES=1024`); `_step_projectiles` integrates each per tick (gravity × per-weapon `gravity_scale`), raycasts the per-tick segment against enemy hitboxes (interest-grid broadphase, *cheaper* than the full-range hit-scan query it replaced) + structures (M4.5 penetration reuse), present-time stepping (no per-shot rewind), distance-traveled falloff. Pure math in `shared/sim/projectile.gd` (shared with the future M7 cosmetic tracer).
- **Fire-mode selection** (AUTO/SEMI/BURST) — per-weapon `fire_modes`/`burst_count`, `SET_FIRE_MODE` control msg, server-enforced in the fire gate via `Weapon.fire_allowed`.
- **Secondary weapon slot + quick-swap** — two-slot per-client state (primary + universal PISTOL sidearm) with independent ammo/reload/fire-mode, `SWAP_WEAPON` control msg, `WEAPON_SWAP_TICKS=12` equip lockout (< reload). (Re)spawn/deploy restores a fresh loadout (both slots full, back on primary).
- New telemetry: `proj/projhit/projlive/projdrop/swaps`.

**Deterministic proof (authoritative, AGENTS.md §10):** `tests/projectile_gate_test.gd` — bullet travels (not instant), drops under gravity, hits a stationary target and applies damage via the real `_step_projectiles`; per-slot ammo persists across swap; swap lockout; respawn resets both slots.

**128-bot fleet gate — PASS on game2** (server pinned P-cores 0-3, bots 4-31, Docker `full` profile): `winner=0 t0=57 t1=0 elapsed=269s cap_events=3`, **proj=207 projhit=19 projlive=163 projdrop=0 swaps=32**, **peak tick=24.71ms < 33.3**, peak agg=15.5 Mbit/s. Evidence: `docker/srvlog-20260623-124223.log`. (≤48 smoke `ci/m5.5_p1_test.sh` also PASS: winner=1, proj=127 projhit=15 swaps=11, peak 15.80ms.) The projectile pool adds ~1ms over M5-P1's 24ms baseline; `projdrop=0` → the cap was never threatened at 128p.

**P2 will hook suppression near-miss detection into `_step_projectiles`** (a clean comment seam is left in the candidate loop).
