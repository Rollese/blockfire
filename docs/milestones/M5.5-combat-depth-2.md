# M5.5 — Combat Depth II (Ballistics, Loadout, Suppression, Melee, Throwables)

**Status:** **DONE ✅ (P1+P2+P3, 2026-06-24)** — P1 ✅ (2026-06-23) · P2 ✅ (2026-06-23) · P3 ✅ (2026-06-24) · **Follows:** M5 (Land) · **Interleaves with:** M7 (its ballistics feed the rendered client) · *(new milestone added 2026-06-17 from the BattleBit feature-gap review)*

**Objective:** Close the remaining BattleBit-feel combat gaps at the **sim layer** before the rendered client locks in its feel: **projectile ballistics (bullet drop + travel)**, **fire-mode selection**, **secondary weapon**, **armor class**, **suppression**, **melee (knife + sledgehammer)**, and **flashbang + impact grenades**. Server-authoritative, shared rules in `shared/sim/`, bot-gated + deterministically proven (the M4.5 mould). VFX/feel deferred to M7.

Spec: [`docs/specs/combat-depth-2.md`](../specs/combat-depth-2.md) — the build contract; where it and this doc differ, the spec wins.

## Why this milestone exists / sequencing

Surfaced in the 2026-06-17 feature-gap review (BattleBit comparison). The owner accepted nine gaps; seven are sim-layer combat mechanics (this milestone), two are presentation and live in M7 (death-recap card → M7-P1; audio → M7-P2). Rejected in the same review: friendly fire, sniper breath-hold/sway, player spotting, grapple/zipline, attachment-depth, riot-shield/suicide-C4/binoculars, squad-leader orders/commo-rose.

**Ballistics feeds M7 now.** Bullet drop changes client prediction, and M7-C2 is in flight. Per owner direction (2026-06-17) the ballistics model is **decided now** so M7 builds **projectile-aware** prediction (cosmetic client tracer; server-confirmed hits) instead of hit-scan — avoiding a later prediction refactor. The rest of M5.5 follows the M4.5→M7 pattern: prove the mechanic + budget headlessly here; tune *feel* on the visual client (AGENTS.md §10).

## Key design decisions (from the brainstorm, owner-approved 2026-06-17)

- **Stepped projectiles**, not analytic hit-scan-with-drop: bullets are genuine entities, dodgeable, lead-required — the real BattleBit feel. Present-time stepping, **no per-step lag-comp rewind** (travel masks latency). Spawn at the shooter's command tick. Projectiles ride a server pool (disjoint ID range), **not** the per-tick snapshot — clients derive a cosmetic tracer from the fire event.
- **Suppression is gameplay-affecting** (raises effective spread + aim-sway while suppressed), not visual-only; the 1-byte scalar also drives the M7 screen FX.
- **Armor is one simplified class** (Light/Medium/Heavy) bundling body-damage reduction + move-speed + capacity, helmet folded in — not separate helmet/vest/backpack slots.
- **Death feedback is a lightweight recap card** (killer/weapon/distance/HP), **not** a replay killcam (BattleBit has no killcam; no position reveal) — and it lives in **M7-P1**, not here.
- **Audio** is reserved as an M7-P2 spec (designing it before the renderer exists is premature).

## Budgets

- **Server tick** mean step **< 33.3 ms** at 128 bots. **P1 projectiles are the headline risk** (O(live bullets × broadphase steps)); cap (`MAX_LIVE_PROJECTILES`) + ttl + interest-grid culling bound it; degrade the projectile cap before dropping bot count. P2/P3 add cheap O(N)/O(1) work next to the dominant `snap` cost.
- **Bandwidth:** no new per-tick stream; suppression + blind add ≤2 bytes/pawn.

## Gate

Per phase: mechanics proven **deterministically** (scripted scenario — led shot connects with drop; HEAVY takes less than LIGHT; suppressed spread rises; back-stab instant-kills; flash blinds in-LOS; impact detonates on contact), **budget + match completion** proven on the **128-bot fleet** (AI-dependent combat counters reported, not gated — AGENTS.md §10). All phases: Conquest still reaches a winner.

## Deferred to M7 (presentation/feel)

Tracer/projectile visuals + muzzle flash · suppression blur/shake/muffle · flashbang white-out + deafen + angle-of-view scaling · melee/sledge/swap animations · fire-mode HUD indicator · armor visual diffs · **death-recap card (M7-P1)** · **audio (M7-P2)**.

## P1 — Ballistics & weapon handling — CLOSED ✅ (2026-06-23)

Plan: [`docs/plans/2026-06-17-m5.5-p1-ballistics.md`](../plans/2026-06-17-m5.5-p1-ballistics.md) (8 tasks). Built on branch `m5.5-p1-ballistics` via `subagent-driven-development` (Task 3 — the authoritative fire-path change — two-stage read-only reviewed; full-implementation final review = READY TO MERGE). 11 commits; suite **672 run / 0 failed**.

**What shipped:**
- **Stepped projectiles** replace hit-scan. `_fire_shot` spawns a projectile into a server pool (`MAX_LIVE_PROJECTILES=1024`); `_step_projectiles` integrates each per tick (gravity × per-weapon `gravity_scale`), raycasts the per-tick segment against enemy hitboxes (interest-grid broadphase, *cheaper* than the full-range hit-scan query it replaced) + structures (M4.5 penetration reuse), present-time stepping (no per-shot rewind), distance-traveled falloff. Pure math in `shared/sim/projectile.gd` (shared with the future M7 cosmetic tracer).
- **Fire-mode selection** (AUTO/SEMI/BURST) — per-weapon `fire_modes`/`burst_count`, `SET_FIRE_MODE` control msg, server-enforced in the fire gate via `Weapon.fire_allowed`.
- **Secondary weapon slot + quick-swap** — two-slot per-client state (primary + universal PISTOL sidearm) with independent ammo/reload/fire-mode, `SWAP_WEAPON` control msg, `WEAPON_SWAP_TICKS=12` equip lockout (< reload). (Re)spawn/deploy restores a fresh loadout (both slots full, back on primary).
- New telemetry: `proj/projhit/projlive/projdrop/swaps`.

**Deterministic proof (authoritative, AGENTS.md §10):** `tests/projectile_gate_test.gd` — bullet travels (not instant), drops under gravity, hits a stationary target and applies damage via the real `_step_projectiles`; per-slot ammo persists across swap; swap lockout; respawn resets both slots.

**128-bot fleet gate — PASS on game2** (server pinned P-cores 0-3, bots 4-31, Docker `full` profile): `winner=0 t0=57 t1=0 elapsed=269s cap_events=3`, **proj=207 projhit=19 projlive=163 projdrop=0 swaps=32**, **peak tick=24.71ms < 33.3**, peak agg=15.5 Mbit/s. Evidence: `docker/srvlog-20260623-124223.log`. (≤48 smoke `ci/m5.5_p1_test.sh` also PASS: winner=1, proj=127 projhit=15 swaps=11, peak 15.80ms.) The projectile pool adds ~1ms over M5-P1's 24ms baseline; `projdrop=0` → the cap was never threatened at 128p.

**P2 hooked suppression near-miss detection into `_step_projectiles`** (the clean comment seam left in the candidate loop) — see below.

## P2 — Survivability & suppression — CLOSED ✅ (2026-06-23)

Plan: [`docs/plans/2026-06-17-m5.5-p2-survivability.md`](../plans/2026-06-17-m5.5-p2-survivability.md) (7 tasks). Built on branch `m5.5-p2-survivability` (TDD, per-task). Suite **691 run / 0 failed** (+19 over P1's 672).

**What shipped:**
- **Armor class (LIGHT/MEDIUM/HEAVY)** — pure `shared/sim/armor.gd` (`body_mult` 1.0/0.85/0.7, `speed_mult` 1.0/0.95/0.9, helmet `headshot_lethal`). `Pawn.armor_class` drives move speed in `step()`; set from class at spawn via `Loadout.armor_for`. **Recon was already removed (M12-P1)**, so the four live classes span all three tiers: **MEDIC=LIGHT, ASSAULT=MEDIUM, ENGINEER/SUPPORT=HEAVY**. In `_apply_pawn_damage`, body damage is scaled by the victim's tier; a sub-threshold **finishing** headshot vs HEAVY is downgraded off the instant-kill (routes through as body damage / DBNO). Note: headshots are not one-shot kills in this game (AR head = 50 vs 100 HP), so the helmet matters on finishing shots against damaged targets.
- **Suppression (gameplay-affecting)** — pure `shared/sim/suppress.gd` (`accrue`/`decay`/`spread_penalty_deg`). `Pawn.suppression` (0..1) accrues in `_step_projectiles` when an enemy bullet's segment passes within `SUPPRESS_RADIUS=2.5 m` (point-to-segment distance, closer = more), decays `0.04`/tick, and above `0.25` widens the shooter's own fire ray via a new `reconstruct_ray(..., suppression_spread_deg)` term (a deployed bipod still overrides it to zero). Applies to bots too, so the gate exercises it.
- **Replication** — own suppression quantized to **1 byte on SELF_STATE** (the local player's own, for the deferred M7 screen FX). *Deviation from the plan's snapshot byte:* the per-pawn snapshot field-mask is a full u8 (no free bit) and remote suppression need not replicate (spec §2), so it rides the backward-compatible SELF_STATE trailing-append instead — cheaper (1 byte to each human, not N²) and mask-safe. Client stores `_suppression` for M7.
- New telemetry: `supp` (near-miss accruals/window).

**Deterministic proof (authoritative, AGENTS.md §10):** `tests/armor_test.gd` (body/speed tiers, helmet finishing-headshot downgrade), `tests/suppress_test.gd` (accrue/decay/spread monotonicity), `tests/projectile_gate_test.gd` (`test_heavy_takes_less_body_damage_than_light`, `test_heavy_helmet_saves_from_finishing_headshot`, `test_near_miss_accrues_suppression` — all via the real `_apply_pawn_damage` / `_step_projectiles`), `tests/combat_test.gd` (suppression widens spread; bipod override), `tests/protocol_test.gd` (SELF_STATE suppression round-trip + old-sender default).

**128-bot fleet gate — PASS on game2** (server pinned P-cores 0-3, bots 4-31, Docker `full` profile, TICKETS=50): `winner=0 t0=29 t1=0 elapsed=307s < 600 (ticket exhaustion, not the time fail-safe) cap_events=4`, **peak supp=1323** (suppression strongly exercised at 128p density), **peak tick=26.91 ms < 33.3**, peak proj=296, peak agg=15.6 Mbit/s, **0 script errors**, 128 players. Evidence: `docker/srvlog-p2fleet-20260623-155605.log`. (≤48 direct run on game2 also clean: peak tick 15.78 ms, peak supp 309, proj 128, agg 3.3 Mbit/s.) The +1 byte/SELF_STATE suppression field left bandwidth in line with P1 (15.5 → 15.6 Mbit/s); tick sits ~2 ms over P1's 24.71 ms baseline, well within budget.

**Deliberate v1 simplification:** the spec §2 armor table lists *ammo/throwable capacity* per tier; v1 implements the two combat-defining axes (body-damage mult + move-speed mult + helmet) and **does not** scale spawn mag-reserve / grenade / bandage counts by tier. Capacity is the weakest of the three BattleBit armor levers and orthogonal to the gated mechanic; deferred until a tier wants a capacity identity (one-line hook at the spawn loadout if so). Code review (2026-06-23) verdict APPROVE with this as the only open nit.

**Deferred to M7 (per spec §2):** suppression screen blur/shake/audio-muffle and armor visual differences (the byte + scalar are replicated and ready). **Suppression screen FX done + visual-validated 2026-06-24** (tunnel vignette + desaturate + edge blur from the SELF_STATE byte; audio-muffle already shipped) — see M7-art-ux.md "Suppression screen FX". Armor visual diffs still open.

## P3 — Melee & throwables — CLOSED ✅ (2026-06-24)

Branch `m5.5-p3-melee-throwables` (TDD, 7 tasks). Plan: [`docs/plans/2026-06-17-m5.5-p3-melee-throwables.md`](../plans/2026-06-17-m5.5-p3-melee-throwables.md).

**What landed:**
- **Melee** — pure `shared/sim/melee.gd` (`in_reach` / `is_backstab` rear-arc / `best_target` nearest-frontal). `Msg.MELEE` (zero-payload trigger). Server `_resolve_melee`: cooldown-gated (`MELEE_COOLDOWN_TICKS=24`); the nearest frontal enemy takes `MELEE_DAMAGE=50`, and a hit inside the 60° rear arc is an **instant kill** routed through the M4.5 `Revive.is_instant_kill` path (`headshot=true`), bypassing DBNO.
- **Sledgehammer (Engineer-only)** — `Loadout.has_sledgehammer`. The Engineer's melee marches the aim ray and carves the struck structure cell via `_damage_structure(SRC_MELEE, …, SLEDGE_STRUCT_RADIUS=1.5 m)`; with no structure in reach it bonks a pawn for `SLEDGE_PAWN_DAMAGE=35`. Knife classes cannot damage building walls (explosive/melee-only per M11). Carve is **radius-based** on the chunked M11 store (not a fixed HP amount).
- **Impact grenade** — `Grenade.IMPACT` + `is_contact_fuse`. `_step_impact` detonates on first contact (structure march / ground / point-blank enemy within `IMPACT_CONTACT_RADIUS=1 m`) using the frag blast, instead of the fuse.
- **Flashbang** — `Grenade.FLASHBANG`, no damage. `_detonate_flash` blinds every living pawn (any team — indiscriminate, BattleBit-style) within `FLASH_RADIUS=8 m` that has line-of-sight to the blast (`_store.march` occlusion), setting `Pawn.blind_until_tick` (`FLASH_BLIND_TICKS=90`).
- **Replication** — remaining-blind-ticks ride the owner-only `SELF_STATE` message as 1 byte (after the P2 suppression byte; backward-compatible decode), **not** the per-pawn snapshot EntityState: the white-out is a local screen FX with no third-person visual, exactly as P2 replicated suppression.

**Plan deviations (recorded):** (1) `SELECT_THROWABLE` message skipped — the existing `GRENADE_THROW` already carries a per-throw type byte, so flashbang/impact ride it (server validates the id); persistent client-side selection is an M7 UI concern. (2) Blind rides `SELF_STATE`, not EntityState/snapshot as the plan's pre-P2 wording assumed. (3) Sledge structure carve is radius/source-based (chunked store), not the plan's fixed `SLEDGE_STRUCTURE_DAMAGE` amount.

**Deterministic proof (authoritative, AGENTS.md §10):** `tests/melee_test.gd` (reach / rear-arc back-stab / nearest-target), `tests/grenade_test.gd` (type constants + `is_contact_fuse`), `tests/grenade_gate_test.gd` (impact detonates on wall contact while frag flies past; knife frontal=body-damage / back-stab=instakill / cooldown; Engineer sledge carves a wall while a knife does not; flashbang blinds an exposed pawn, is blocked by a wall (LOS), and spares out-of-radius pawns), `tests/protocol_test.gd` (MELEE encode; SELF_STATE blind round-trip + old-sender default), `tests/loadout_test.gd` (sledge Engineer-only), `tests/pawn_test.gd` (`is_blinded`). Suite **713/0**.

**128-bot fleet gate — PASS on game2** (server pinned P-cores 0-3, bots 4-31, Docker `full` profile, map `conquest_proving_grounds`): `winner=0 t0=40 t1=0 elapsed=302s < 900 (ticket exhaustion, not the time fail-safe) cap_events=4`, **melees=7 backstabs=3 sledge=8 flashes=3 flashblinds=44 impacts=6** (every P3 mechanic exercised emergently under load), **peak tick=24.62 ms < 33.3**, peak agg=15.6 Mbit/s, **0 script errors**, 128 players. Evidence: `docker/srvlog-m5.5-p3-20260624-090158.log`. Scripts: smoke `ci/m5.5_p3_test.sh`, fleet `docker/run-m5.5-p3-gate.sh` (hard-gates melees/flashes/impacts + M3 baseline; reports backstab/sledge/flashblind which are also proven deterministically). The +1 byte/SELF_STATE blind field left bandwidth unchanged (15.6 Mbit/s, == P2); tick sits ~2 ms under P2's 26.91 ms.

**Presentation in M7:** the flashbang **white-out** render is **DONE ✅ 2026-06-24** — `HudModel.blind_intensity` (pure, tested) + a topmost full-screen white `HudView` overlay driven by the SELF_STATE blind byte; visual-validated on the `.128` client (auto-deploy + `--flash-test` + `--shot-after` screenshot; merge `4a630b9`).
